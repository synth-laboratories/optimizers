Shared platform · synth.container_bundle.v1

Portable container bundle standard

One immutable image, one content-addressed source bundle, one manifest that binds them, and one launcher that verifies and records everything it did.

Hypothesis
Every supported task runtime can be launched, verified and restarted through one capability-dispatched path, with no benchmark-name conditionals in generic code.
Verdict
Specified. Not yet proven end to end in this campaign.
Confidence
None — no bundle has been built, uploaded or launched under this schema yet.
Why
The v0.7 MAPO lanes ran against the in-process DungeonGrid environment, not through a published bundle, so every receipt row below is honestly empty.

Image and source binding

The manifest is the only place the image digest, the source digest, the task contract and the build revision meet. Everything downstream cites its digest.

  • Mutable tags are display-only; an immutable registry digest is required.
  • Credentials never enter the source bundle or the manifest — only secret references, resolved at launch and never logged.

Downloader and launcher

One CLI path, eleven ordered steps, and a conformance suite that exercises the failure half of each one.

  • Restart uses the same immutable bundle, so a restarted container is the same container by construction rather than by convention.

Boundaries and who may read what

Each row is a boundary drawn in the maps above. Crossing it changes ownership, visibility, or both.

BoundaryRule
RegistryImmutable. A digest is required; a tag is a label for humans.
Object storeContent-addressed. Bytes are verified before extraction, not after.
SecretsReferenced by name in the manifest, resolved at launch, never written to logs or bundles.
Generic orchestrationMay read declared capabilities only. A benchmark-name branch here is a defect.
